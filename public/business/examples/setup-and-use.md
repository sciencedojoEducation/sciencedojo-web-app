# Setup and usage notes

## Files

- client-handover-module.html: the complete module, with readable/editable HTML, CSS and JavaScript in one file.
- learning-design.pdf: readable task, objectives, storyboard and evaluation plan; learning-design.md is the editable text version.
- assessment-guide.pdf: readable practical exercise, sample response and scoring guide; assessment-guide.md is the editable text version.
- client-review-checklist.pdf: readable review and handover checklist; client-review-checklist.md is the editable text version.
- setup-and-use.pdf: these instructions in a readable PDF; setup-and-use.md is the editable text version.

## Run the module

Download the module and any companion documents you want, and keep them in one folder. Serve the folder from an ordinary static web server you control, with JavaScript enabled. You can also try opening client-handover-module.html directly in your chosen browser; check that saved-file route before relying on it with learners. No ScienceDojo account, application server, API, external font or runtime service is required. Your organisation supplies and pays for any hosting it chooses.

The companion document links are relative: they work when the documents remain beside the HTML file. JavaScript is needed for the decision practice; the task, application prompt, example response and rubric remain readable without it.

## Responses and privacy

Decisions and typed responses exist only in the current page. Nothing is sent, stored centrally or saved after a reload or close. There are no analytics, network calls, learner accounts, automated marking, certificates, LMS reporting or resumption between sessions. Use the fictional scenario and avoid personal or confidential information. For a real workshop, agree a separate process for collecting work samples.

## Editing

Read, print or share the PDFs using a PDF reader. To edit the supporting documents, open the matching .md files in a text editor; these are plain-text Markdown files. Open the HTML in a text editor to change the module source. The HTML includes the styles and decision runtime rather than an authoring-app project. Retest interactions, links, and layouts after changing code.

The sample is intended for modern browsers. Browser, mobile, keyboard and zoom checks must be recorded separately before production claims are made. It is a static browser example, not a SCORM package, LMS compatibility certification or accessibility certification.
